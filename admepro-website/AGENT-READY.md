# SEO and agent readiness (what the build produces)

All of this is generated by `build/build.mjs`, so it stays correct when content changes.

## For search engines
- One title (max 60 characters) and description (max about 160) per page, EN and AR. Blog posts use `seoTitle` / `seoDescription` in the post JSON when the visible title is longer.
- Canonical, hreflang (EN/AR/x-default), Open Graph, Twitter cards, sitemap with language alternates and images, schema.org (Organization, WebSite, Service, CreativeWork, BlogPosting, FAQPage, BreadcrumbList, CollectionPage).
- Production build is indexable, staging build is `noindex` with a "TEST SITE" ribbon.

## For AI agents and assistants
| What | Where |
|---|---|
| Markdown copy of every page | `<page-url>/index.md`, also returned for `Accept: text/markdown` (Apache rule in `.htaccess`) |
| Site map for LLMs | `/llms.txt`, `/ar/llms.txt`; all text in one file: `/llms-full.txt`, `/ar/llms-full.txt` |
| Crawler rules | `/robots.txt` allows search + AI crawlers, with `Content-Signal: search=yes, ai-input=yes, ai-train=no` (change `ai-train` in `build.mjs` if you want training allowed) |
| API discovery | `/.well-known/api-catalog` (RFC 9727), `/api/openapi.json`, `/api/projects.json` |
| Agent skill | `/.well-known/agent-skills/index.json` |
| Link headers on `/` | `api-catalog`, `describedby` (llms.txt), `service-desc` |
| In-browser agents (WebMCP) | read-only tools `search_admepro`, `list_admepro_projects`, `get_admepro_contact` (see end of `site.js`) |
| Security contact | `/.well-known/security.txt` |

Not included on purpose: an MCP server card or OAuth discovery. There is no MCP server or login on this site, and publishing one would be untrue.
